# VellumScribe Design & Brand Review — 2026-10-25

Prepared by: designer subagent (UI/UX & visual identity owner)
Scope: first public release (F-Droid / alternative app stores)
Constraint honoured: no application source or config was touched; implementation
findings are handed to `coder`. Only `docs/design/**`, `assets/**`, `*.svg` and
`*.md` were edited.

## Summary

The design system is cohesive, considered, and genuinely minimalistic: one brand
mark rendered everywhere, a restrained zinc palette with user-owned note colours,
a clear type hierarchy (Plus Jakarta Sans UI / Newsreader reading / JetBrains Mono
data), and good state coverage (empty, loading, error, offline).

**Verdict: not yet release-ready.** There are no Critical findings, but four High
findings — two WCAG 2.2 AA accessibility defects (light-mode contrast on small
text, invisible keyboard focus), one visual defect (light-mode colours inverted on
the batch action bar), and one documented-but-unimplemented accessibility claim
(reduced motion). Fix these before the F-Droid/public release; everything else is
polish or Low risk.

Brand mark and launcher/adaptive icons are **release-ready**: consistent geometry,
correct safe zones, correct background colour (`#09090B` matches the tile), and
splash colour matches `capacitor.config.json` `backgroundColor` (`#121215`).

## What is good (honest positives)

- **Brand mark** (`assets/brand/vellumscribe-mark.svg`): original geometry, white
  on `#09090B` ≈ 21:1 contrast, compact mark sits well inside the Android adaptive
  safe zone (extremes ≈ 27% from each edge), legible as a silhouette down to small
  sizes.
- **Icon set consistency**: legacy `ic_launcher.png` / `ic_launcher_round.png`,
  adaptive foreground (`ic_launcher_foreground.png`, tile excluded), monochrome
  adaptive, and all splash screens are generated from one source of truth by
  `scripts/generate-brand-assets.mjs`; `values/ic_launcher_background.xml` =
  `#09090B` matches the tile; splash `#121215` matches capacitor `backgroundColor`;
  `public/favicon.svg` is byte-identical in geometry to the brand mark.
- **Dark mode**: contrast is strong throughout (zinc-400+ on `#0c0c0e` ≈ 5.3:1+).
- **State design**: `SyncStatus`, `TranscriptionProgressCard`, `ModalErrorFallback`,
  `ModalLoadingFallback`, `ErrorBoundary` are well considered; empty states with
  CTAs in `EventNotesList` and `ArchiveSection`; `RecentNotesSection` empty state
  doubles as a creation hub.
- **Touch targets**: primary bars use `min-h-[44px]`/`min-w-[44px]`; list cards are
  keyboard-operable (`role="button"`, `tabIndex={0}`, Enter/Space handlers).
- **Density/rhythm**: consistent `px-6`/`p-3.5` page padding, `gap-2`–`gap-4`
  component rhythm, hairline `zinc-200/zinc-800` borders, `shadow-2xs` elevation.

## Findings

Severity key: Critical = blocks release; High = fix before release; Medium = fix
soon after; Low = polish / observation.

### Critical

None.

### High

**H-1 — Light-mode small text fails WCAG AA contrast (≈2.5:1, needs 4.5:1).**

`text-zinc-400` (`#a1a1aa`) on light surfaces (`#fafaf9`, `bg-white`) renders at
≈2.5:1 for small text — below the 4.5:1 AA threshold. Widespread helper/meta text.

- `src/components/EventNotesList.tsx:462` — note meta row (`text-xs text-zinc-400`)
- `src/components/EventNotesList.tsx:612` — note date (`text-zinc-400`)
- `src/components/RecentNotesSection.tsx:90-91` — intro description (`text-xs text-zinc-400`)
- `text-zinc-400` appears across panels/settings; dark mode is compliant
  (≈5.3:1 on `#0c0c0e`).

Fix: darken small helper text to `zinc-600` or darker on light surfaces (zinc-600
≈ 7.7:1 on white), keep `zinc-400` only for dark mode or on darker card surfaces.
Do not use `zinc-400` for 11px–14px text on `#fafaf9`/`bg-white`.

**H-2 — Batch action bar colours inverted in light mode.**

`src/components/BatchActionBar.tsx:263`: `bg-zinc-950 text-white` applies in light
mode, `dark:bg-zinc-100 dark:text-zinc-950` in dark mode — the exact opposite of
the app shell (`bg-[#fafaf9]` light). On a light theme the CAB is a near-black bar
in a near-white app, which looks broken on a home-screen task switcher and in
screenshots/store listings.

Fix: swap so light mode is `bg-white text-zinc-900` and dark mode is
`bg-zinc-950 text-white` (match the header pattern in `src/App.tsx:346`).

**H-3 — Invisible keyboard focus (WCAG 2.4.11 AA).**

`focus:outline-none` is used with no visible replacement, so keyboard focus
disappears:

- `src/components/note-editor/NoteTitleBar.tsx:57` — note title input
- `src/components/note-editor/NoteTitleBar.tsx:65` — tag/label pill
- `src/components/NoteEditorWriteFirst.tsx:661` — note title textarea
- `src/components/NoteEditorWriteFirst.tsx:670` — note body textarea
- `src/components/EventNotesList.tsx:724` — type filter `<select>`

Fix: add the established pattern `focus:ring-1 focus:ring-indigo-500` (or
`focus:border-indigo-500`) to each, matching `SettingsView.tsx:775` and the select
in `SettingsView.tsx:775`.

Related sloppiness: `focus:outline-hidden` is used in 13 places
(`App.tsx:353`, `ArchiveSection.tsx:208`, `CloudConnectModal.tsx:584/599/613`,
`ChecklistEditor.tsx:107/130`, `EventNotesList.tsx:661/724/849`,
`NoteEditorChrome.tsx:123`, `NoteSecurityModal.tsx:286/303`, `NoteShareModal.tsx:482`)
but is **undefined** — it appears in neither `src/index.css` nor any Tailwind config
— so it is dead CSS. Where paired with a real focus style it is harmless; where it
stands alone it does nothing (browser default ring survives). Remove or replace
with intentional focus styles.

**H-4 — No `prefers-reduced-motion` handling anywhere.**

Zero matches for `prefers-reduced-motion` in `src/`. `animate-spin` (loaders),
`animate-pulse` (header dot, segment pills), `animate-fade-in` (modals/toasts), and
`hover:scale-102` (CTAs) run unconditionally. `ACCESSIBILITY.md` claims the OS
reduced-motion setting is respected — this is unverified/inaccurate until implemented.
WCAG 2.2 AA 2.2.2 requires user control over auto-started motion; decorative spin
and pulse should yield to the preference.

Fix: add a `prefers-reduced-motion` layer in `src/index.css` that reduces
`animate-spin`/`animate-pulse` to opacity-only, disables `hover:scale-*`, and keeps
transitions short; then the `ACCESSIBILITY.md` claim is honest. Implementation
belongs to `coder`.

### Medium

**M-1 — AppLogo inverts the brand mark in dark mode.**

`src/components/AppLogo.tsx:33`: the badge gradient flips in dark mode
(`dark:from-zinc-100 ... dark:text-zinc-950`), rendering a **dark mark on a light
tile** — the inverse of the brand (white mark on `#09090B`) used everywhere else
(favicon, launcher, splash). On a dark phone theme the app logo reads as a
different logo.

Fix: keep the near-black tile + white mark in both modes
(`bg-gradient-to-br from-zinc-900 via-zinc-950 to-black text-white` unconditionally),
or simplify to a solid `#09090B` tile.

**M-2 — Manifest maskable icon clips the tile; theme colour jumps.**

`public/manifest.json:5-12` uses `favicon.svg` (which carries the near-black tile)
for purpose `any maskable`. Under maskable clipping the tile corners are sliced by
the safe-zone mask; the white mark itself is inside the safe zone, but the sliced
black square looks unfinished on home screens. Also `theme_color`/`background_color`
`#121215` (dark) jumps against the light-mode app (`#fafaf9`) on PWA launch.

Fix (design asset added): `assets/brand/vellumscribe-mark-maskable.svg` — same
mark geometry, **no tile**, transparent background, sized for the maskable safe
zone. Wire a `maskable` icon entry pointing at it (and keep `any` as the tiled
favicon) in `public/manifest.json`; revisit `theme_color` for light mode. Manifest
edits are application config — hand to `coder`.

### Low

**L-1 — Mark dot may vanish at 16 px.** The dot (r ≈ 5.25% of the mark) renders
below ~1 px at favicon size; stems are ≈1 px. The V silhouette remains readable,
but at 16 px the dot can drop out/dither on some screens. Acceptable; note for
icon review. If 16 px legibility matters, ship a simplified 16 px variant
(arms + stem, no dot).

**L-2 — Touch targets have zero slack in places.** Recent-notes scroll chevrons and
modal close buttons are exactly 24 × 24 CSS px (`p-1` + `w-4`/`h-4`) — compliant
with the 24 × 24 CSS px target but brittle under subpixel rounding. SyncStatus
pills (`px-2.5 py-1 text-xs`) sit at ≈24 px line-height boxes. Compliant; keep
`min-h-[24px]`/`min-w-[24px]` if these are ever reskinned.

**L-3 — AppLogo duplicates brand geometry.** `src/components/AppLogo.tsx:48-56`
re-inlines the mark SVG instead of referencing
`assets/brand/vellumscribe-mark.svg`. It is currently identical (verified), but
this is drift risk: any mark change must be applied in two places.

**L-4 — Init loader uses a non-brand glyph.** `index.html:85-97` draws an
emerald square with a pen-like path at first paint, while the Android splash uses
the brand mark. Minor brand inconsistency at first paint; optional.

**L-5 — `docs/design/brand.md` shape language was imprecise.** It claimed `2xl`
corners on surfaces; surfaces are `rounded-xl`, with `2xl`–`3xl` on cards/modals.
Fixed in this review (one-line edit).

**L-6 — No store-listing graphics in repo.** No feature graphic, screenshots, or
promo images found under `assets/` or `metadata/` (only root `metadata.json`). For
F-Droid/alt-store listings these will be needed; commission from the brand mark
(white on `#09090B`, generous safe zone) rather than screenshotting the UI.

## Recommendations — priority order for release

1. **H-3** focus indicators (quick, high accessibility impact).
2. **H-1** light-mode small-text contrast.
3. **H-2** CAB colour inversion (visual polish; affects store visuals).
4. **H-4** `prefers-reduced-motion` (makes `ACCESSIBILITY.md` honest).
5. **M-1** AppLogo dark-mode inversion; **M-2** maskable icon + new
   `assets/brand/vellumscribe-mark-maskable.svg`.
6. Low items (L-1…L-6) post-release or with the next design pass.

All implementation findings are handed to `coder`; no application source or config
was modified in this review.
