# VellumScribe GUI/Design Audit — 2026-10-28

**App:** VellumScribe — offline-first multimodal note-taking (Android via Capacitor, web SPA)
**Repo:** Perchemop/VellumScribe @ main, version 3.1.1 (`package.json`)
**Prepared by:** designer subagent (GUI/design owner)
**Constraint honoured:** no application source or config touched; this report and files under `docs/design/` only. Implementation findings belong to `coder`.

## 1. Scope, method and evidence

### What was audited

Every user-visible surface in `src/components/`: app shell (`App.tsx`), note editor write-first (`NoteEditorWriteFirst.tsx`, `NoteEditorChrome.tsx`), home lists (`EventNotesList.tsx`, `RecentNotesSection.tsx`, `ArchiveSection.tsx`, `VirtualizedNotesList.tsx`), transcript viewer (`transcription/TranscriptViewer.tsx`, `TranscriptionProgressCard.tsx`), settings (`SettingsView.tsx` + 10 panels), modals/sheets (`CloudConnectModal.tsx`, `FirstTimeUserGuideModal.tsx`, `AppUpdateModal.tsx`, `AudioRecordingModal.tsx`…), error/loading fallbacks (`ErrorBoundary.tsx`, `ModalErrorFallback.tsx`, `ModalLoadingFallback.tsx`), brand (`AppLogo.tsx`), shared UI (`SyncStatus.tsx`, `BatchActionBar.tsx`, `ChecklistEditor.tsx`, `AiProvenanceBadge.tsx`, `LiveRegion.tsx`, `PreviousRunNotice.tsx`), plus `index.html`, `public/manifest.json`, `public/favicon.svg`, `public/maskable.svg`, `assets/brand/*`, `metadata/fdroid/feature-graphic.svg`, `src/index.css` (Tailwind v4 via `@tailwindcss/vite`; no `tailwind.config.*`), `vite.config.ts`, `ACCESSIBILITY.md`, `docs/design/*` (brand, 2026-10-25 reviews).

Tailwind facts from code: palette is zinc-based (`bg-[#fafaf9]` light / `bg-[#0c0c0e]` dark shell; hairline `zinc-200/zinc-800` borders; `shadow-2xs` elevation; `rounded-xl` surfaces, `2xl`–`3xl` cards/modals). Type: Plus Jakarta Sans (UI), Newsreader (reading), JetBrains Mono (data) via Google Fonts with `media=print` + `onload` render-hint. `motion` (framer-motion) is a dependency but **not imported anywhere in `src/`**.

## 2. What is good (honest positives, none invented)

- **Cohesive visual system**: one restrained zinc palette, consistent type scale (text-xs captions through text-xl headings), spacing rhythm (`px-6`/`p-3.5` page padding, `gap-2`–`gap-4` component rhythm), hairline borders, `shadow-2xs` elevation, `rounded-xl/2xl/3xl` shape language. Matches `docs/design/brand.md`.
- **Dark mode**: strong contrast throughout (zinc-400+ on `#0c0c0e` ≈ 5.3:1+; brand mark white on `#09090b` ≈ 20:1).
- **State coverage**: empty states with CTAs (`EventNotesList`, `ArchiveSection`, `RecentNotesSection` hub), loading (`ModalLoadingFallback`, `SyncStatus`, `TranscriptionProgressCard`, index.html init loader), error (`ModalErrorFallback`, `ErrorBoundary`, transcription error branch, import validation), offline (`SyncStatus` offline pill), post-crash notice (`PreviousRunNotice`).
- **Keyboard on list cards**: `role="button"`, `tabIndex={0}`, Enter/Space handlers on note cards, recent cards, transcript segments; `min-h-[44px]`/`min-w-[44px]` touch targets throughout; FAB 56×56 px.
- **Focus rings where applied**: editor title/body inputs (`focus:ring-1 focus:ring-indigo-500`), note cards (`focus:ring-2 focus:ring-zinc-400`), several selects.
- **Reduced motion**: `prefers-reduced-motion: reduce` layer in `src/index.css` (disables `animate-spin`/`animate-pulse`, kills `hover:scale`, shortens transitions) — `ACCESSIBILITY.md` claim is now accurate (prior H-4 resolved).
- **Prior release-blockers fixed**: light-mode contrast sweep (`text-zinc-600 dark:text-zinc-400`, 193 sites), `BatchActionBar` light colours, `AppLogo` dark-mode tile, maskable icon wired in `manifest.json`, onboarding modal Escape, focus-rings — per `review-2026-10-25.md` commit `ee28509`.
- **Brand**: original mark (white V-quill stem+dot on `#09090b` tile) rendered identically in favicon, maskable icon, AppLogo, init loader, feature-graphic.svg. No lorem text, no dead controls observed, no unstyled controls.
- **Voice/tone**: concrete, honest copy; errors say what failed and what to do next (`PreviousRunNotice`, restore-failed messages).

## 3. Findings (severity order)

Severity key: **Blocker** = cannot release; **Critical** = fixes before release; **Serious** = fix soon; **Moderate** = fix this cycle; **Minor** = polish. Contrast figures marked "computed" are derived from Tailwind color values in code, not measured from pixels (no screenshots available this session).

### Blocker / Critical — none

No finding blocks release. The app renders, loads without console errors (visual job run `40662660919` success), and has no unstyled or broken controls on the audited surfaces.

### Serious

**S-1 — Keyboard focus invisible on the editor's event `<select>` (note editor chrome).**

- Screen/state: note editor → header chrome, event selector, keyboard focus.
- What is wrong: `<select>` carries only `focus:outline-hidden` with **no replacement ring**, so keyboard focus disappears on a native control (WCAG 2.4.11 Focus Appearance, AA). Same dead `focus:outline-hidden` (no ring) suppresses focus on the app-logo header button (`App.tsx:358`), the ChecklistEditor item text input (`ChecklistEditor.tsx:107`), and the NoteShareModal textarea (`NoteShareModal.tsx:488`).
- Evidence: `src/components/NoteEditorChrome.tsx:123` (`className="…focus:outline-hidden cursor-pointer…"`); `App.tsx:358`; `ChecklistEditor.tsx:107`; `NoteShareModal.tsx:488`. Contrast: not applicable (missing focus indicator).
- Fix: replace `focus:outline-hidden` with the established pattern `focus:ring-1 focus:ring-indigo-500` (already used on editor inputs, `EventNotesList.tsx:724`, `SettingsView.tsx:776`) or remove it so the browser default ring survives. Do this for all four sites.

**S-2 — Error screen ignores light/dark setting and its detail text fails even large-text contrast.**

- Screen/state: ErrorBoundary crash panel (any route, error state).
- What is wrong: the fallback is hardcoded `bg-zinc-950 text-zinc-100` regardless of the app's `darkMode` state — a light-mode user hitting an error gets a pitch-black panel. Its error detail text is `text-xs font-mono text-zinc-600 dark:text-zinc-400` on `bg-zinc-950/80`; computed light-mode contrast of zinc-600 (`#52525b`) over near-black ≈ **2.8:1**, below the 3:1 large-text AA minimum (and far below 4.5:1 for small text).
- Evidence: `src/components/ErrorBoundary.tsx:89`–`106`; contrast computed from Tailwind values (zinc-600 `#52525b`, zinc-950 `#0a0a0c` composited at 80% over zinc-900).
- Fix: derive the panel's background from `darkMode` like the rest of the shell (`bg-[#fafaf9] dark:bg-[#0c0c0e]`); use `text-zinc-900 dark:text-zinc-300` (or darker) for detail text so it passes 3:1+ in both themes.

**S-3 — Transcript viewer empty-state helper text fails AA small-text contrast.**

- Screen/state: TranscriptViewer → "segments" tab when no segments exist (`No timestamped segments available for this transcript.`).
- What is wrong: `text-stone-500` (`#78716c`) on `bg-stone-50` (`#fafaf9`) computes to ≈ **4.2:1**, below the 4.5:1 AA threshold for small text. The transcript panel is also the only surface using the `stone` palette (see M-1).
- Evidence: `src/components/transcription/TranscriptViewer.tsx:279`; contrast computed from Tailwind values.
- Fix: darken to `text-stone-600` (≈ 6.4:1) or move the helper onto a darker surface.

**S-4 — (covered by S-1; no fourth serious item found)** — none. Remaining focus-ring omissions are folded into S-1.

### Moderate

**M-1 — Color-system split: TranscriptViewer uses `stone`, the rest of the app uses `zinc`.**

- Screen/state: transcript viewer, AI tasks & summary panel vs. shell, editor, lists, settings.
- What is wrong: headers, tabs, badges, segment rows and copy in `TranscriptViewer.tsx` are `text-stone-*`/`bg-stone-*`/`border-stone-*`, while every other surface is zinc. The two color families sit side by side when a transcript is opened from a note, so the app looks like two design systems.
- Evidence: `src/components/transcription/TranscriptViewer.tsx` (15+ stone classes, e.g. `:150`, `:193`, `:264`, `:294`) vs. `src/App.tsx`, `NoteEditorWriteFirst.tsx`, `SettingsView.tsx` (zinc only).
- Fix: migrate TranscriptViewer to the zinc token scale (zinc-800/200 body, zinc-500/600 meta, zinc-900 headings) or explicitly document stone as a transcript-only subsystem in `docs/design/brand.md`.

**M-2 — `ModalErrorFallback` references a nonexistent color (`border-zinc-250`).**

- Screen/state: any modal error fallback (component load errors in modals).
- What is wrong: `border-zinc-250` is not a defined Tailwind shade (scale is 50–950), so the class is dropped. Error modals may render borderless — in light mode a white card on the page background with no hairline edge looks unfinished/broken.
- Evidence: `src/components/ModalErrorFallback.tsx:23` (`border border-zinc-250 dark:border-zinc-800`).
- Fix: `border-zinc-200 dark:border-zinc-800` to match every other modal (`ModalLoadingFallback`, `NoteSecurityModal`, etc.).

**M-3 — Blocking `window.confirm` for note delete inside the editor.**

- Screen/state: note editor → More (⋮) sheet → Delete.
- What is wrong: `window.confirm('Delete this note?')` is a blocking browser dialog, inconsistent with the in-app confirm modals used everywhere else (batch trash/delete, empty trash) and jarring on Android WebView.
- Evidence: `src/components/NoteEditorChrome.tsx:407`.
- Fix: replace with the same inline confirm-modal pattern used by `BatchActionBar` (confirm target + Execute/Cancel buttons, Escape-dismissible).

**M-4 — Dialogs lack focus containment and accessible naming; Escape coverage is mixed.**

- Screen/state: all modals and sheets (cloud connect, settings modal, share, security, revisions, AI key/summary, onboarding, attach/more sheets).
- What is wrong: overlays are `fixed inset-0` with backdrop-click close but no `aria-modal="true"`, no `aria-labelledby` on most, and no focus trap — keyboard focus can escape to the background behind an open modal. The attach and more sheets in `NoteEditorChrome` close only via their backdrop button (aria-label "Close") — no Escape key handler. Icon-only checklist delete button in `ChecklistEditor` rows has no accessible name (opacity-0 hover icon).
- Evidence: `src/components/NoteEditorChrome.tsx:196–202`, `:286–293`; `ChecklistEditor.tsx:112–118`; modal markup across `src/components/*.tsx`.
- Fix: add `role="dialog" aria-modal="true" aria-labelledby` to each overlay, Escape handlers on every sheet (re-use `useModalBackHandler`), and `aria-label` on the checklist delete button.

**M-5 — Settings metrics toggle has no visible keyboard focus indicator.**

- Screen/state: Settings → Architecture & Diagnostics → Usage Metrics (opt-in) toggle.
- What is wrong: custom checkbox built on `sr-only` peer input with `peer-focus:outline-none` on the track — keyboard focus lands on the hidden checkbox with no visible ring (WCAG 2.4.11).
- Evidence: `src/components/SettingsView.tsx:1602–1609`.
- Fix: add a visible focus ring to the toggle track/label (e.g. `peer-focus:ring-2 peer-focus:ring-indigo-500`) and drop `peer-focus:outline-none`.

**M-6 — Entrance-animation utility classes are undefined; intended motion never runs.**

- Screen/state: every modal, toast, and the empty state (~30 usages).
- What is wrong: `animate-fade-in`, `animate-in fade-in`, `animate-in zoom-in-95 duration-200` appear throughout (`App.tsx`, `BatchActionBar.tsx`, `EventNotesList.tsx`, `CloudAiConsentModal.tsx`, `NoteRevisionsModal.tsx`, …) but Tailwind v4 is configured with no animation plugin and `src/index.css` defines no `@keyframes` for them — they are silent no-ops. Overlays and toasts snap in rather than fading. No a11y regression (the `prefers-reduced-motion` layer still works because nothing animates), but the designed motion intent is not realized.
- Evidence: grep over `src/` (37 matches) vs. `src/index.css` (no keyframes; only `prefers-reduced-motion` layer) and `package.json` (no `@tailwindcss/forms` or animate plugin).
- Fix: either define the keyframes + utilities (`animate-fade-in`, `zoom-in-95`) in a CSS layer, or remove the classes so the design intent is not implied. Keep `prefers-reduced-motion` handling for any motion that ships.

**M-7 — Placeholder text is under-contrast on light surfaces.**

- Screen/state: note editor title/body (`placeholder:text-zinc-400`), note search, archive search, settings inputs.
- What is wrong: `placeholder-zinc-400` (`#a1a1aa`) on white computes to ≈ **2.6:1** — below AA. Placeholders are secondary UI, but low-contrast placeholders fail to communicate editability.
- Evidence: `src/components/NoteEditorWriteFirst.tsx:664,673`; `EventNotesList.tsx:661`; `ArchiveSection.tsx:208`; contrast computed from Tailwind values.
- Fix: use `placeholder-zinc-600` (≈ 7:1) on light surfaces, keep `placeholder-zinc-400` only on dark.

### Minor

**m-1 — Brand mark geometry duplicated in three places (drift risk).**

- Screen/state: app-wide brand (header, init loader, favicon, launcher).
- What is wrong: the mark SVG path/geometry is inlined in `assets/brand/vellumscribe-mark.svg`, `src/components/AppLogo.tsx` (lines 39–56), and `index.html` (lines 74–96) — a fourth variant appears in `metadata/fdroid/feature-graphic.svg`. All verified identical today, but any mark edit must be applied in 3–4 places.
- Fix: single source of truth in `assets/brand/`; reference it (inline the canonical file or a shared component) in `AppLogo.tsx` and `index.html`.

**m-2 — AboutPanel uses a plain "V" text badge instead of the brand mark.**

- Screen/state: Settings → About & Guide.
- What is wrong: the app-header/about surfaces use `AppLogo` (tile + mark + wordmark), but `AboutPanel` renders a letter "V" in a rounded square — a different mark in the same app.
- Evidence: `src/components/settings/AboutPanel.tsx:13` (`<div …>V</div>`).
- Fix: use `AppLogo` or the canonical mark SVG there.

**m-3 — Unused UI code shipped: `RichBodyEditor` and the `motion` dependency.**

- Screen/state: bundle, not a screen.
- What is wrong: `src/components/note-editor/RichBodyEditor.tsx` is exported but never imported anywhere (write-first editor uses a plain textarea) — dead UI code in the bundle. `motion` (framer-motion) is installed but not imported in `src/` — bundle bloat on every load (perceived performance).
- Evidence: `src/components/note-editor/index.ts:2` re-exports it; no other match for `RichBodyEditor`; `package.json` `motion ^13.1.1` with zero `from 'motion'` matches in `src/`.
- Fix: remove `RichBodyEditor` (or wire it into the editor) and drop `motion` unless animation is planned (ties to M-6).

**m-4 — Theme flash at first paint in light mode.**

- Screen/state: app launch (index.html init loader).
- What is wrong: `<body>` and the loader are `#121215` while the light app shell is `#fafaf9` — users in light mode see a dark splash, then the app snaps light. The loader also sets `system-ui` fonts instead of the brand's Plus Jakarta Sans.
- Evidence: `index.html:48,53–111` vs. `src/App.tsx:344`.
- Fix: make the loader shell match the light theme (or keep dark and accept it as the brand splash, but then don't switch to light abruptly); load brand fonts in the loader.

**m-5 — No raster store graphics committed.**

- Screen/state: store listings (F-Droid / alt stores).
- What is wrong: `metadata/fdroid/feature-graphic.svg` exists (SVG source, 1024×500) but stores require PNG/JPEG; no PNG is committed or generated by a script.
- Evidence: `metadata/fdroid/feature-graphic.svg` (notes "rasterise to PNG … before submitting").
- Fix: rasterise the SVG to a 1024×500 PNG and check it in, or add an assets script.

**m-6 — No `forced-colors` (high-contrast mode) consideration.**

- Screen/state: Windows High Contrast / forced colors mode.
- What is wrong: no `@media (forced-colors: active)` overrides anywhere; `bg-transparent` inputs with colored borders could lose their edges, and custom-styled controls don't adapt.
- Evidence: grep `forced-colors` → 0 matches in `src/`.
- Fix: audit the highest-traffic inputs under forced colors; add overrides if the app targets desktop Windows users (advisory — Android has no forced-colors equivalent).

**m-7 — Bottom-nav labels are `text-[10px]`.**

- Screen/state: mobile bottom navigation.
- What is wrong: 10 px labels are at the edge of readability; conventional for bottom navs, but worth a device check. Not a failure on its own.
- Evidence: `src/App.tsx:611,620,629,638`.
- Fix: verify legibility on device; no code change required unless it reads poorly.
